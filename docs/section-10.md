# פתרונות לכל תרגילי ההרחבה – סעיף 10

## 1. סטטיסטיקה למנהל

`GET /api/admin/stats` מחזיר `{"userCount":2}` (המספר משתנה לפי הנתונים).
ללא טוקן: 401. משתמש רגיל: 403. מנהל: 200.

## 2. טוקן ל־60 שניות

מפעילים את הפרופיל `short-token`, מתחברים ומבצעים בקשה עם הטוקן. אחרי יותר מדקה אותה בקשה מחזירה 401.
פרופיל זה משנה רק את טוקן הגישה; טוקן החידוש נשאר תקף לשבעה ימים.
בדיקת Java מאמתת שהפרופיל מחזיר תוקף של 60,000 מילישניות ושבקשת HTTP עם טוקן חתום שפג תוקפו נדחית ב־401.

</div>

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=short-token
```

<div dir="rtl">

## 3. הוספת תפקיד בלי התחברות מחדש

מנהל שולח `PUT /api/admin/users/{id}/roles` עם גוף `{"roles":["ROLE_ADMIN"]}`.
התפקיד מתווסף לתפקידים הקיימים. הבקשה אינה מוחקת תפקידים אחרים.
הטוקן הישן של המשתמש מאפשר מיד גישה לכתובות מנהל: `JwtAuthFilter` טוען את התפקידים מהמסד בכל בקשה ולא מסתמך על רשימת התפקידים הישנה שבטוקן.
הדגמה: בדיקות 23–27 בקובץ ההרחבות, ללא פעולת login בין שינוי התפקיד לבדיקה.

## 4. החלפת סיסמה

`PUT /api/user/password` עם גוף `{"oldPassword":"Student123!","newPassword":"Changed123!"}`.
המשתמש מזוהה מהטוקן, ולא ממזהה שנשלח בגוף. הסיסמה הישנה נבדקת ב־BCrypt; סיסמה ישנה שגויה מחזירה 401.
סיסמה חדשה חייבת להיות באורך 8–72 תווים ולא יותר מ־72 בתים ב־UTF-8. ההצלחה מחזירה 204.
הסיסמה החדשה נשמרת כ־Hash בלבד. טוקני החידוש הקודמים מבוטלים.
טוקני גישה קיימים נשארים בתוקף עד פקיעתם (עד 15 דקות); שינוי סיסמה כשלעצמו אינו מבטל אותם.

## 5. חסימת משתמש

מנהל שולח `PUT /api/admin/users/{id}/enabled` עם `{"enabled":false}`.
הטוקן הקיים מפסיק לעבוד מיד, login נדחה וטוקני החידוש מבוטלים.
שליחת `{"enabled":true}` מאפשרת התחברות מחדש. טוקני חידוש שבוטלו אינם חוזרים לעבוד.
טוקן גישה ישן שטרם פג עשוי לחזור לעבוד לאחר הסרת החסימה, משום שהמסנן קורא את המצב העדכני מהמסד.

## 6. אבטחה ברמת מתודה

`SecurityConfig` מפעיל `@EnableMethodSecurity`.
הפעולות הניהוליות ב־`UserManagementService` מוגנות גם ב־`@PreAuthorize("hasRole('ADMIN')")`.
כלל URL ב־`SecurityConfig` מגן על בקשות HTTP לפי הנתיב. `@PreAuthorize` מגן על קריאה למתודת ה־Service דרך ה־Bean שמנוהל ב־Spring, גם אם הקריאה לא הגיעה מ־Controller.
קריאה פנימית באותה מחלקה אינה עוברת דרך ה־Proxy ולכן אינה מפעילה את בדיקת האנוטציה.
בדיקות Java קוראות ישירות ל־Service: משתמש רגיל נדחה ומנהל מצליח.

## 7. Refresh Token

login מחזיר גם `refreshToken` ו־`refreshExpiresInMs`. טוקן הגישה תקף ל־15 דקות; החידוש לשבעה ימים.
`POST /api/auth/refresh` מקבל `{"refreshToken":"..."}` ומחזיר זוג טוקנים חדש, ללא צורך בטוקן גישה תקף.
בכל חידוש הטוקן הישן מבוטל ומוחלף בחדש (rotation); שימוש חוזר בו מחזיר 401.
טוקן חידוש הוא ערך אקראי קריפטוגרפי בן 256 ביט. נשמר במסד רק SHA-256 שלו, עם משתמש, תאריך תפוגה ודגל ביטול.
נעילה טרנזקציונית מונעת משתי בקשות מקבילות לצרוך בהצלחה את אותו טוקן.
טוקן שפג תוקפו, בוטל או שייך למשתמש חסום נדחה. טוקן חידוש אינו יכול לשמש כטוקן Bearer לגישה למשאבים.
שינוי הסיסמה וחסימה מבטלים את כל טוקני החידוש של המשתמש.

## הרצה ובדיקות

דרישות: Java 21 ו־Maven. להרצה הרגילה צריך PostgreSQL 16 או Docker.

</div>

```bash
docker compose up -d --wait
mvn verify
mvn spring-boot:run
```

<div dir="rtl">

ברירת המחדל של בדיקות Maven היא מסד H2 זמני, במצב תאימות PostgreSQL. הבדיקות יוצרות ומוחקות רק את סכמת מסד הבדיקות.
לבדיקת PostgreSQL אמיתי, יוצרים **מסד נפרד לבדיקות** ומגדירים `TEST_DB_URL`, `TEST_DB_USER`, `TEST_DB_PASSWORD` לפני `mvn verify`.
אין להפנות את משתני הבדיקות למסד שיש בו נתונים שרוצים לשמור: `ddl-auto=create-drop` מיועד למסד בדיקות בלבד.
GitHub Actions מפעיל את הבדיקות מול PostgreSQL 16 זמני בכל push ובכל Pull Request.

בדיקות HTTP ידניות: מריצים את `http/security-tests.http` ואז `http/extension-tests.http` בסביבת `dev` ב־IntelliJ.
אפשר גם להריץ את שני הקבצים אוטומטית מול שרת שכבר פועל, באמצעות Node.js 18 ומעלה:

</div>

```bash
node scripts/run-http-tests.mjs
# Or a different port:
node scripts/run-http-tests.mjs http://localhost:8081
```

<div dir="rtl">

בדיקות ה־HTTP רושמות משתמשי דוגמה חדשים ומשנות אותם; יש להריץ אותן מול סביבת לימוד.
בדיקת ה־60 שניות מפורטת בבדיקה 20 בקובץ המקורי. מול שרת שפועל בפרופיל `short-token` אפשר להריץ `node scripts/test-expiry.mjs`: הסקריפט ממתין 61 שניות, מוודא 401 ואז מחדש את הטוקן ובודק שוב גישה. גם בדיקה זו נכללת ב־GitHub Actions. מריצים את שאר בדיקות ה־HTTP בפרופיל הרגיל (15 דקות).

</div>
